# 实验计划、指标和研究路线

本文件是预先定义的实验设计，不是结果表。v0.1 只有合成数据上的程序测试；尚未访问本项目真实 CSV、调用用户的 DeepSeek API 或采集真实教师轨迹。

## RQ1：能否制造数据真正支持的任务？

固定来源组和任务预算，对比规则模板、无事实约束的 LLM 出题、事实包约束出题，以及加入代码门槛和 Critic 的完整流程。无约束基线仍须在安全环境内运行，不执行模型任意代码。

主要指标为独立审计的任务有效率、错收率、数值规格覆盖、题面—rubric 一致性、答案泄漏率和不可支持结论比例。模型输出 schema pass 不能替代这些指标。

分母应写清楚：初始提案数、修订提案数、去重后任务数、审核后任务数都记录。若修改后有效率升高但多数困难案例被剔除，应同时报告覆盖损失，而不是只展示成功比例。

## RQ2：多视角候选是否改善有价值场景覆盖？

对比只用 context 切换、只用信号规则、多视角候选以及加入稳定对照的版本。当前尚未实现稳定对照挖掘；不可提前填实验结果。

按来源实验、工况、组件、事件类型、时间尺度和数据质量分层统计覆盖。候选数、候选组数、接受 Case 数、不同任务数和独立实验数分别报告。去重前后数量和随机抽样的重复程度都应公开。

不要将 4,130 个历史索引位置与新一版复杂案例数直接比较得出“规模提升”。计数单位不同，比较无效。

## RQ3：三角色及评审方式带来什么？

比较无 Critic、同模型独立角色、跨模型 Critic、人工校准。固定其余采样、事实和预算，才能看清模块贡献。替换 Critic 后的自评分上升不是证据，应使用固定的独立盲审样本和一致 rubric。

为控制同源相关性，置信区间优先按原始来源组重采样，而不是把同一案例几十个问法当几十份独立证据。来源很少时，明确统计不确定性，不用大量相关任务掩盖问题。

## RQ4：题目是否真的考察 Agent 调查能力？

真实 solver 至少比较：直接读取给定统计的单轮回答、简单固定工具流程、可自选工具的 Agent。在固定可见数据和预算下测量最终答案及证据质量。

进一步进行无数据、无工具、打乱数据、移除关键证据等诊断。它们检验是否存在文本捷径或任务未真正依赖数据，而不是自动证明因果可识别性。允许短而正确的工具路径，不能以调用次数作为能力总分。

v0.1 固定测量规范只能验证引导式调查。评估自主选窗应增加大范围上下文及允许多个有效窗口的评分机制，不能继续用隐蔽的单一作者窗口精确匹配。

## RQ5：成本与规模如何变化？

记录每个角色的请求数、成功/失败/重试、token usage、耗时，以及每个最终独立有效任务的摊销成本。保留失败开销。不要硬编码会变化的 API 价格；用实验当日价格快照计算费用。

先跑少量来源的开发实验，分析失败归因，再增加规模。优先扩展真实场景覆盖，而不是对同一任务采样很多轨迹。教师模型和制造任务模型可独立选择。

## 数据划分限制

同源原始实验、重叠窗口、同一 Case 的所有任务和轨迹必须留在同一 split。标签/异常名字不能通过源 ID 泄漏。真实资料中若每类故障只有一次源实验，就不能同时声称“每类都在训练和测试中出现”且“测试全部来自新实验”；需要改变研究问题、补新源或明确为同源评测。

开发集反复调试不再充当独立测试集。不要把先前 16 个人工案例打磨后的成绩叫最终 Benchmark 成绩。
