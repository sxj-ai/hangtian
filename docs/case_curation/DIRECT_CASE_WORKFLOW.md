# 当前流程：由当前助手直接整理案例

这是最新用户要求，替代此前“必须使用subagent”和“调用Qwen API”的安排。

当前工作只到案例材料：发现候选、读取数据、整理完整过程、解释证据、复算、去重、自查和保存。当前助手直接完成，不调用subagent，不调用Qwen、DeepSeek或其他模型API，不生成问题、任务JSON、题目槽位、评分规则或解题轨迹。本次对话只修订交接说明；新对话按用户发出的启动提示词实际整理案例。

## 每个案例如何推进

1. 读取固定的项目说明、来源/通道字典、证据限制、候选与已有案例索引。核对来源哈希，不依赖长聊天中的记忆。
2. 为一个完整案例建立独立文件目录和简洁输入说明，记录完整数据位置、源哈希、相关比较案例、质量问题、待核查事实和版本。
3. 读取完整相关过程，保留前史、变化、后续/恢复、正常反例和例外样本。没有前史就明确写缺失，不补写。
4. 使用实际统计脚本复算决定性事实；能用独立实现时采用，并准确区分“另一个数值实现”和“同一函数重跑”。
5. 写案例JSON和解释：观测是什么、支持什么判断、为什么有意义、还不能判断什么；不顺手出题。
6. 切换到自查阶段，重新读取原始证据与案例，不只读上一段总结。检查数值、语义、区别、参考适用性和证据边界。
7. 修订另存版本，重跑受影响的检查，更新哈希绑定。接受、暂缓、合并和拒绝都留记录。
8. 更新私有案例簿、去重/血缘索引和run_state.json，每5—8个候选汇总一次进度；这不是必须产出的案例数。

## 自查如何如实记录

四个提示词文件是同一助手使用的不同工作阶段，不是四名代理。作者与审查者相同，`review.independence`明确填“same-assistant self-review”，并说明独立数值复算是否实际执行。不能把角色切换描述成独立模型、独立专家或独立子代理审查。

案例可以在实际数值检查和明确记录的自查后标记为材料层面的accepted；报告中同时保留未做独立语义审查的限制。结构验证、哈希一致、自查通过都不证明物理根因或论文结论正确。

## 保持不同批次一致

固定每次运行使用的来源、提示词、schema、工具版本及判定标准；每个案例都有完整输入和证据文件。记录缺项、错误、返修和合并，按家族比较，不把复杂案例与简单案例的通过率混算。不承诺长对话下质量天然一致，靠可复核材料和固定检查减少漂移。

原始数据与已有100题保持不变。历史材料来自哪些模型或子代理，仍保留原始记录；当前整理不需要调用它们。后续是否出题、怎么出题，不在当前启动流程中安排。
