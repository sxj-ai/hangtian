# 当前XJTU-SPS数据可以整理多少案例

判断日期：2026-10-09。以下“预计”是依据实际数据结构作出的策展判断，不是已经验收的数量，也不是统计置信区间。

**建议先做约30—40个候选案例，严格检查完整性、实质区别与重复后，预计可保留约25—35个核心案例。** 如果保留同一家族下有实际数据差异的扩展实例，可以有更大的材料库，但应单独列为变体。当前没有足够证据承诺100个实质不同的核心案例。

此前提出的“约100案例、500任务”是论文规模的规划建议。它没有经过本轮数据容量核查，不能反过来要求这23份来源凑出100案例。实际应先以这份数据能支撑的案例库检验pipeline，再决定是否补充独立实验或其他数据。

## 重新核查了什么

本轮在云服务器重新读取全部23份遥测CSV及其工况/标签，核对原始遥测SHA256，与前期审计一致。重新计算了332周期中的低辐照恢复、各负载实测活动区间、全零连续段、重复及冲突时间戳。没有调用模型API或运行GPU。

| 已核实项目 | 数量或范围 | 对案例数量的意义 |
|---|---:|---|
| 原始来源记录 | 23份 | 是来源层数量，不代表23次已证明独立的采集 |
| 正常命名来源 | 6份，1,470,495行 | 包含长期行为与反例，不能只用一个正常文件作参考 |
| 故障标签来源 | 17份，378,220行 | 不等于17种可由测量唯一识别的根因 |
| 全部遥测 | 1,848,715行、332周期 | 行数/周期数不直接换算成案例数 |
| 正常周期 | 264 | 大量重复相同名义计划，主要贡献过程变化与稳健性检查 |
| 故障来源周期 | 68，即17份各4周期 | 每个来源的前后与演变应优先保留为完整案例 |
| 正常低辐照阶段 | 264段都观察到持续P_SA>5的记录 | “低输出后来恢复”是重要正常反例，264次不算264种现象 |
| 上述阶段中整体中位数≤1 | 50段 | 支持检查“只看中位数会误判”的分析场景 |
| 全33测量通道为零 | 1个连续段，共11,399行 | 应完整研究质量结构，不能切成上百个全零案例 |
| 当前材料与任务 | 22包、100题、19份原始来源 | 去重核心案例数此前尚未完成登记 |

P_SA恢复定义为连续20条原始记录高于给定阈值，以真实时间戳计算相对低辐照段首记录的秒数；5是探索用的阈值，不是设备故障线。负载活动统计采用电流>1且连续至少10条记录，同样不是工程合格标准。

## 正常数据有哪些尚未充分利用的内容

| 来源 | 周期数 | 低辐照到P_SA持续>5的偏移范围 | Load1活动开始相对名义阶段的偏移范围 |
|---|---:|---:|---:|
| 2024.10.18 | 24 | 245—539秒 | −4—29秒 |
| 2024.10.20 | 18 | 245—273秒 | −3—16秒 |
| 2024.10.23 | 94 | 244—841秒 | 21—540秒 |
| 2024.10.29 | 90 | 245—843秒 | 16—577秒 |
| 2024.9.18 | 4 | 245—536秒 | 21—27秒 |
| 2024.9.19 | 34 | 245—539秒 | 20—132秒 |

这说明正常参考不是一条固定曲线。长记录后期，负载较晚投入与太阳能较晚恢复可能同时存在。材料应保留实际负载时间和此前运行历史，否则会把不同原因的“低输出很久”混在一起。

时间参照必须写清。例如10.23第94周期，距低辐照开始的恢复偏移约841秒；距实测Load1活动开始约301秒。这两者衡量不同的过程，不能混称为指令延迟，也不能认为两个统计结果矛盾。

六份正常文件的工况字段取值集合相同：Irradiation为0/300/1000，Temperature恒25，Incidence_Angle为0/90，Load_Signal为0/1/2/3。因此，当前不具备不同工况温度、连续光照扫描、不同轨道配置等广覆盖证据。传感器温度在变化，不等于工况温度设置有多个水平。

正常侧可先提出8—14个候选方向：完整正常供电过程、短等待与长等待后恢复、长记录负载投入逐渐推迟、活动时长变化、参考来源适用性、孤立温度尖峰与轻微时间戳冲突等。这里存在重叠：如果“投入推迟”和“时长缩短”只是同一过程的两个描述，应合并；如果某个尖峰只换了发生行号，应作为同类实例。

## 故障记录适合组织成什么

下表按来源列的是**待整理的观测场景**。标题来自私有来源元数据，不能直接给解题Agent，也不代表已经证明对应根因。

| 来源或来源组 | 有用的完整场景 | 不能据此声称 |
|---|---|---|
| BAT_degradation | 已测电池组分担不均、外部正常对比 | 没有本次健康前史，不能写寿命退化轨迹 |
| BAT_open circuit | 某已测组电流消失、其他组增加的前后过程 | 不能由三组测量恢复全部电池能量收支 |
| BCR_increased power loss | SA/BCR测量关系及母线随周期变化 | P_SA−P_BCR不能直接命名为器件损耗；不能简单写持续下降 |
| BCR_open circuit | BCR输出变化与不同负载服务先后变化 | 某负载没工作不直接等于该负载独立故障 |
| BCR_short circuit | 冲突时间戳；全零尾段及采样结构切换 | 全零不能当作已证实的物理停机或独立诊断成功证据 |
| Bus_insulation breakdown | 母线仍有测量值、负载侧响应缺失 | 缺接线和保护状态，不确定漏电路径/功率 |
| Bus_open / Bus_short | 母线和负载低/零值，上游仍有记录 | 仅稳态相似特征不能推出唯一开路/短路原因 |
| Load1/2/3_open circuit | 对应支路电流缺失、仍有电压，其他阶段仍可观察 | 停用时零电流不能当故障，电压存在不等于有服务 |
| PDM1/2/3_open or short | 对应支路电压、电流均缺失，母线仍有值 | 不能把数据集已合并的开/短路标签再次拆成唯一原因 |
| SA_component deterioration | 持续较低输出与已测电池参与的关联 | 无本次健康前史，不能做退化起点或剩余寿命 |
| SA_partial open | 输出减弱、负载响应与电池参与的前后过程 | 不能估计实际损坏支路数 |
| SA_partial short | 低辐照阶段持续低输出，与正常等待恢复比较 | 不能只用低中位数判故障 |

故障来源侧可先列16个物理观测实例，另把BCR_short拆为两类不同质量问题，共18个整理候选。16个物理观测实例只覆盖约9个主要行为家族；Load与PDM各三条支路、BAT两来源、Bus开短路等之间存在明显同族关系。它们是否保留为多个核心案例，要看工况和证据是否产生实质区别，而不是只换通道编号。

还有4个可核查但不预先计入核心数的线索：BCR_open后续负载服务退出是否构成独立后续事件；BCR_loss少量冲突时间组是否有不同影响；Bus_insulation孤立温度跳点；BCR_short前段在质量限制下能否支持独立观测案例。若只是父事件的补充证据，就合并回父例。因此18—22是源侧候选预算，不是已验收产量。

一个具体限制：BCR_short第三周期起点为原始行10268，但连续全零从10270才开始。第三周期前两条仍有非零通道，不能写成“第三周期全程33列全零”。第四周期才全部处于该零值尾段。

## 跨来源比较可以增加分析价值，但会复用数据

可优先考虑约8个方向：三组Load与对应PDM的实测差异、Bus开短路的可辨识边界、BAT两种记录的差异及限制、SA记录与完整正常恢复、BCR变化与母线/负载变化的区别、不同正常来源的参考适用性。

这些比较只有在“比较后多回答了一个原单源案例无法回答的具体问题”时才单独成例。重复把某正常文件加入不同包、枚举所有两两组合、把三组类似比较称成三种新机制，都不能增加核心多样性。所有比较案例必须列出父来源与父案例，不增加独立采集数。

当前新17包全部共享9.18正常的R1/R4，旧solar额外使用10.23第94周期。共享参考会把很多包连到同一个证据依赖图中。不能按题随机划分训练/测试后声称来源独立；增加包数解决不了这个问题。

## 数量估计如何得出

| 层次 | 本轮建议 | 说明 |
|---|---:|---|
| 有依据的候选搜索空间 | 约34—46 | 故障/质量18—22、正常8—14、比较8—10；区间之间仍可能重叠 |
| 首批优先整理 | 约30—40，交接登记36条 | 先保留有明确证据入口的方向，不追上界 |
| 严格合并后核心案例 | 预计25—35 | 去掉支路换名、同过程拆分和没有独立分析价值的比较；属于判断，尚未逐例验收 |
| 更大的实例库 | 暂不定承诺值 | 正常周期/同族支路可作变体和稳健性样本，必须另列计数 |
| 来源/独立性 | 原始来源23，独立性未被证明 | 派生案例不产生新的实验采集 |

目前可以有信心说“还值得整理更多案例”，但不能说“已经知道能验收35例”，更不能说“只能有35例”。新发现若具有不同完整过程和不同证据要求，可以增加核心数；发现重复或解释受限，应减少数量。

对后续出题也不能固定乘以5。一个核心案例可能只支持1—2个有区别的调查目标，也可能支持几个；有的只适合做反例或验证附件。现有100题应保留为开发任务实例，与新核心案例建立多对一映射。若希望论文有100个真正不同的案例或很大的独立测试集，应在此轮结果后评估新增来源，而不是通过改写题目达到数字。
