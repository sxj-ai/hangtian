# 概念、研究目标与边界

## 我们建设什么

建设一个把真实遥测组织成可审计分析场景，再制造 Agent 任务的研究系统。研究对象不是只会给出异常标签的分类器，也不是一个可以向卫星发指令的控制器。第一阶段的核心产物是 **Case Library + Task Library + 私有评测依据**；真实工具交互轨迹是下一阶段产物。

| 对象 | 严格含义 | 不等于什么 |
|---|---|---|
| Experiment | 一次原始记录/实验及关联资料 | 一个文件名；一个训练样本 |
| Candidate | 某项检测规则提示值得进一步查看的记录区间 | 已确认故障；已合格案例 |
| Fact Package | 来源、窗口、通道、可复算数值、背景和限制 | 大模型生成的描述性答案 |
| Case | 经审查可用于提出有意义问题的分析材料包 | 必须包含唯一故障结论的事件 |
| Task | 给 Agent 的分析目标、可见范围、工具及私有验证要求 | 换一句话的同题复述 |
| Trajectory | 一次实际执行中的模型消息、工具调用、真实返回及报告 | 出题模型想象的解题过程 |
| Lineage group | 同源实验及其副本、衍生窗口的共同来源组 | 自动由路径推断的分类 |

一案可以多题，一题可以多次执行；三次执行仍是一道题。大量窗口也不会增加独立源实验数量。事件并非所有案例的必要前提：稳定对照、多周期比较、数据质量调查都可以成为场景。

## 不再混用 4,130 与 Case 数量

历史对话报告过：在 23 组实验的工况/标签字段中找到了 4,130 个切换位置。该数字是既有对话中的审计记录，本仓库初始化没有重新读取那些原始 CSV，也没有迁移旧服务器产物。它不是本仓库本次算出的结果，不是案例数量，更不是案例上限。本次合成例子的候选数量与它无关。

历史对话还提到 16 个开发案例和 35 个窗口；它们目前也没有作为真实数据导入本仓库。不得把这里的 `EXP_SYNTH_001` 叫作 XJTU-SPS 实验。

## 三个模型角色不是三个不同模型

`case_curator`、`task_generator`、`task_critic` 是三个职责和三个独立请求上下文。初版均配置 `deepseek-flash`。同模型新会话是角色隔离，不是统计独立的评审者；相关偏差仍需人工和跨模型校准。独立角色也不等于隐藏链式思考采集，本项目只要求简明证据依据和结构化输出。

## 难度的准确表述

计算均值可以是基础单元测试。多个均值加一篇长报告不自动成为复杂任务。调查任务应有依赖证据的选择：检索什么、排除什么、如何处理记录冲突、什么情况下停止。

v0.1 公开固定测量定义，允许围绕给定材料做调查；它属于 `guided_investigation`。不能把它说成已经测量了完全自主的长记录搜索。更大的可见时域、可替代证据窗口、预算约束和交互式反馈，需要另立协议及评分方式。
