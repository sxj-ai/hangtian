# 自主分析任务的修订与验收

2026-10-08，用户明确：题库的目标是考察 Agent 自主分析，而非照预设查询执行。

## 旧版审核结论

T01—T15 逐题复查均需针对自主分析目标修订。每题附6—24项精确查询，共167个查询实例。旧求解提示词要求复制查询，旧验证器将查询完全匹配参考作为通过条件。此前数值验证和有引导任务审查仍有价值，但没有证明自主分析能力。

这不是单纯修改措辞的问题。只从题干删除步骤、却将它们放入 JSON、数据卡、工具示例、文件名或评分规则，仍然不合格。

## 新的接口

- 公开任务：调查目标、必要范围和交付要求；不附测量清单、预判命题、事件答案位置。
- 公开环境：中性记录目录、通道单位、必要语义与已知资料可用性。保留完整选定记录；不导出基于观测形成的内部事件区域与计算结果。
- 通用工具：原始行分页读取、自选行窗口的统计、粗粒度概览、时间轴质量、持续越阈、全零段。全部保留原始采集顺序；不执行模型代码。
- 后台参考：原始材料、已核查事实与可接受结论，用于复核和评价，不提供唯一解题路径。
- 评分：工具证据复算与引用完整性是硬检查；结论相关性、覆盖程度、证据充分性和限定条件由语义审核判断。其他有效分析路径可以通过。证据真实不等于结论正确。

通用提示词为 `prompts/autonomous_generator.md`，后台只允许 `deepseek-flash` 生成角色。新脚本 `scripts/generate_autonomous_batch.py` 仅生成候选，不自动批准，不调用求解角色。任务经逐题审核、绑定候选/公开内容/材料哈希后才能通过 `autonomous.review_gate`。旧版 guided 流程保留作为历史对照。

`autonomous.solve` 已提供新的工具交互循环与审核门槛；本轮不运行真实 Agent。它只发送公开任务和真实工具观测。轨迹中的 `submitted` 只是提交；`verify_evidence` 始终返回 `task_pass: null`，等待针对实际结论的语义审查。尚未实现全自动开放答案评分，不得将它报告成全自动任务验收。

## 审核必须回答的问题

1. Agent 是否需要读取数据才能得出主要结论，还是只凭题面就能回答“证据不足”？
2. Agent 是否自己决定有意义的证据、窗口、比较或解释，而不只是调整调用顺序？
3. 所有模型可见内容是否提供了答案方向、分析路线或预定位事件？
4. 必要语义是否充分，是否存在后台要求但公开目标没有说明的评分条件？
5. 不同的有效分析路径能否得分？泛泛套话或虚构引用能否被拦住？
6. 各题服务的判断是否有实质区别？同源任务须分别运行，不能在同一上下文中继承前题答案。

## 当前边界

数据仍是经过人工选择的有限实验记录，任务是限定材料中的自主调查，并非无限制访问整个服务器或任意代码执行。材料筛选本身也可能降低搜索难度。无步骤提示只是必要条件，难度、工具是否足够、任务区分度还需要通过后续独立 Agent 轨迹验证。

正式试跑顺序：审核新版公开任务及后台标准 → 固定版本与隔离环境 → Agent 自选工具解题 → 核验工具证据和最终结论 → 分别归类题目、工具、评分或求解失败。保存模型动作、工具参数和返回、错误、最终提交及用量；不把供应商隐藏推理当作必须保存的轨迹。


最终产物：`runs/autonomous_tasks_final_001/`，15题经API来源核对与当前助手逐题复审。API提供的私有评分草案不直接作为正式评分；`private/outcome_rubric.json`保存助手审核后的内部标准，并与审题文件绑定哈希。新版公开问题由API产生，助手只编辑内部评价标准。
