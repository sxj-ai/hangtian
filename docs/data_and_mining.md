# 数据接入、Case Mining 与阈值校准

## CSV 是否必须先上传 GitHub？

**不需要，也不建议。** GitHub 保存程序、schema、英文提示词和合成示例。原始 CSV 可以保留在 HPC；运行时 manifest 使用本地绝对路径或相对于 manifest 的路径。真实案例、标签、答案、调用记录默认输出到 `artifacts/` 或 `runs/`，这些目录已被忽略。

当前可以先写通用解析、检测器接口、事实计算、角色请求、校验及审计代码。真正需要访问数据才能定下来的，是通道单位、时间格式、辅助表对齐、同源归组、窗口尺度、异常阈值、正常参照和事件的实际解释。不能靠文件名和聊天记录完成这部分校准。

## 最小接入资料

| 输入 | 目的 | 缺少时怎样处理 |
|---|---|---|
| 一份完整代表性遥测 CSV | 验证表头、时间、原始顺序及局部/长时行为 | 仅做合成验证，不声称真实可用 |
| 同实验的 context 文件 | 核对光照/负载等背景与行对应 | 不问需要这些背景才能回答的问题 |
| 通道字典/传感器说明 | 确认单位、测点、方向和真实物理关系 | 单位留 null；不做物理因果判断 |
| 文件来源/复制/切片记录 | 防止不同名字掩盖同源 | 相关 split 设为 development，等待归组 |
| 标签含义和生成方法 | 区分事件标记、时程标签和真实诊断依据 | 标签私有隔离，不作为自动真值 |

不需要把全部数据塞进一次模型请求。通用代码扫描本地文件，再传小型事实包。使用远程 API 前，操作者必须明确授权该事实包出站；匿名 ID 并不让遥测内容自动变成非敏感数据。

## manifest 约定

`configs/dataset.example.json` 是路径占位模板，不是可直接读取的真实数据。可运行例子在 `examples/synthetic/manifest.json`。`configs/xjtu_sps.manifest.template.json` 列出历史对话中的 33 个通道名，单位全部未知，不代表本次验证了这些文件。

必须给每个源实验一个中性的 ID，不使用 `BAT_degradation`、`Bus_short` 等带答案的 ID。`lineage_group` 根据真实来源指定，不按文件名猜。每组只能属于一个 split。辅助字段显式标为 `context` 或 `private_label`，不能把故障标签误标为公开背景。

`time_kind=seconds` 用数值轴；`datetime` 默认使用 ISO 解析，其他格式设置 `time_format`。一个文件内不要混用有时区和无时区时间。程序保留重复和倒退，不自动修复。左闭右开窗口 `[10,20)` 恰含原始第 10 至 19 条记录，不包含 CSV 表头。

## v0.1 检测器配置

| 检测器 | 关键参数 | 产物 | 不能据此声称 |
|---|---|---|---|
| context_transition | 显式公开的 context 字段 | 相邻值变化的位置 | 指令真实执行时刻 |
| median_step | window_rows、min_step、noise_multiplier | 两侧中位数变化线索 | 物理故障已发生、精确起点 |
| isolated_spike | min_spike、neighbor_tolerance | 与两侧不一致的孤立点 | 传感器一定坏了 |
| all_selected_channels_zero | zero_channels、epsilon、min_zero_rows | 指定列的连续近零段 | 整个航天器全断电 |
| repeated_time / time_reversal | 保留原始顺序 | 时间质量候选 | 可以直接删除重复行 |

当前示例阈值仅为 60 行合成 fixture 设置。不要把 `min_step=5` 或 `context_rows=6` 复制到所有真实通道；不同单位、噪声水平和实验采样率不能共享未经验证的绝对阈值。

## 校准步骤

先把完整来源集合归为开发、训练、验证和测试，不用测试集表现反推阈值。选取开发来源的正常、变化、质量异常等片段，画曲线并核对原始记录；检查检测器的误检与漏检，而非只看候选数量。

逐通道记录绝对阈值依据、局部噪声尺度、最短持续长度、窗口长度及是否存在周期正常变化。变化检测只产生候选；若一个阈值把所有正常负载开关都叫“故障”，应修改命名和后续解释而非掩盖正常候选。

冻结一版配置后，对保留来源运行并抽查各类接受/拒绝场景。超出 `max_rows` 时程序明确报错，不能静默取头部。v0.1 一次加载一个有行数上限的实验，并非已实现外存流式分析；超大单文件需后续实现带窗口重叠的分块处理。

## 尚需实现的扩充

漂移与多周期比较需要时间质量和工况可比性约束；跨源参考检索需要先定义哪些资料对 Agent 可见；稳定对照案例需专门采样，不能只围绕检测到的变化。近重复检测应考虑同一实验的重叠窗口及相邻周期，不能只用字符串去重。

当前三角色工厂可复用这些新事实包，不需要把 prompt 中的职责重新改写成“任意读取全部 CSV”。模型扩窗/请求新证据应通过受限数据服务完成，而不是执行模型给出的任意文件路径或 Python。
